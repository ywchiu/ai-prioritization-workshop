# 步驟一　實作手冊：建立疾病清單

> 這份是**照著做**的操作手冊。想了解方法學依據與「為什麼要這樣做」，請看課程投影片步驟一的章節。

## 0　這一步要交出什麼

| 項目 | 內容 |
|---|---|
| 產出檔案 | `01_candidates_tw.csv` |
| 內容 | 15 至 30 項人畜共通傳染病候選，每項標明對應哪幾類考量、來源與查證日 |
| 大約時間 | 30 分鐘 |
| 這一步**不做**的事 | 不排名次、不篩選、不決定最終 10 項 |

這一步的產出是**候選與理由**，不是名次。清單一旦定案，後面五個步驟都以這份清單為範圍。若漏掉疾病，要先回來補入清單，再繼續後面的步驟。

## 1　開始前準備

**工具**：ChatGPT、Gemini 或 Claude 擇一，登入可用帳號。以下操作三者皆適用。

**開好這幾個瀏覽器分頁**（等一下要用來查證 AI 的回答）：

1. [疾管署官網](https://www.cdc.gov.tw/) →「傳染病與防疫專題／傳染病介紹」分類頁：查我國法定傳染病第一至五類；若網頁失效，從官網搜尋疾病名並記錄待查狀態
2. [農業部動物傳染病分類表（GL000290）](https://law.moa.gov.tw/LawContent.aspx?id=GL000290)：查法定動物傳染病
3. [WOAH Terrestrial Code](https://www.woah.org/en/what-we-do/standards/codes-and-manuals/terrestrial-code-online-access/) 第 1.3 章：查 WOAH 列管疾病

**開好這個檔案**：[`materials/case_data/candidates_tw_2026.md`](../case_data/candidates_tw_2026.md)

這是課程提供、包含已查證線索與待查欄位的 22 項演練候選清單，等一下用來跟 AI 的回答對照。**若要做未看答案的練習，請開全新對話，先不要貼給 AI**：先讓 AI 自己生一份，再拿這份對答案，你才看得出 AI 漏了什麼、多了什麼、編了什麼。

**下載空白範本**：[`01_candidates_tw.csv`](templates/01_candidates_tw.csv)：欄位標題已依本手冊的規格建好，用 Excel 開啟後直接填。

**建立資料夾**：在電腦上開一個「工作坊練習」資料夾，四個步驟的產出都存在這裡。

## 2　原始素材：你要餵給 AI 的東西

這一步**不需要上傳任何檔案**。你要給 AI 的是「九類考量」這份判斷規則，直接寫在指令裡（下一段的指令已經包含）。

九類考量出自方法學第 2 頁，內容是：

| # | 考量 | 白話 |
|---|---|---|
| 1 | 我國之法定傳染病 | 疾管署公告的第一至五類 |
| 2 | 我國之法定動物傳染病 | 農業部公告的甲乙丙類 |
| 3 | WOAH 列管之人畜共通傳染病 | 世界動物衛生組織名單 |
| 4 | 國內疫情現況 | 本土與境外移入、年病例數與死亡數 |
| 5 | 國際疫情現況 | 規模、是否跨國傳播、移入我國可能性 |
| 6 | 造成大流行的潛力 | 是否可能大規模傳播，影響多個地區 |
| 7 | 嚴重度 | 致死率、重症比率、發生率、後遺症比率 |
| 8 | 傳播特性 | 傳播途徑、人畜間傳播能力、R0 |
| 9 | 是否有疫苗或治療藥物 | 有哪些預防或治療方式可以使用 |

**九類是找候選的線索，不是資格考。** 不必九項全中才能列入，中越多也不代表越優先。

## 3　貼這段給 AI

> **這一段就是投影片第 21 頁「Agent 如何生成候選清單」。** 投影片上說的「Agent」，指的就是你正在用的 ChatGPT／Gemini／Claude；所謂「Agent 操作」，就是把下面這段文字貼進對話框。投影片那頁的「交辦內容」與「輸出與檢查」兩欄，合起來就是下面這一段。

整段複製，貼進對話框：

```
請依我國人畜共通傳染病重要性排序方法學第 2 頁的九類考量，從疾管署現行法定傳染病分類中篩出人畜共通者，並補入法定動物傳染病與 WOAH 列管中的人畜共通疾病，產出 15 至 30 項候選，逐項標明對應哪幾類考量。

九類考量為：(1) 我國之法定傳染病 (2) 我國之法定動物傳染病 (3) WOAH 列管之人畜共通傳染病 (4) 國內疫情現況 (5) 國際疫情現況 (6) 造成大流行的潛力 (7) 嚴重度 (8) 傳播特性 (9) 是否有疫苗或治療藥物。

輸出 01_candidates_tw.csv，欄位含：編號、中文名、英文名、人：法定分類、動：法定動物傳染病、WOAH、國內疫情、國際／大流行、嚴重度、傳播特性、疫苗／治療、來源、查證日、納入理由、待查項目。

規則：
- 查不到的欄位一律填「待查」，並在待查項目欄寫明該去哪個系統查，不得以 0 或推測值填補。
- 每一項的納入理由都要指出對應哪幾類考量。
- 來源要寫文件名稱、網址與資料日期；查證日另記本次實際閱讀並核對的日期。來源只有年月時照原樣保留，不自行補上日期。
- 來源要寫文件名稱與網址加日期（例如「WHO Rabies Fact Sheet，2024-06-05」），不能只寫「WHO」或「CDC」。
- 不得把這份候選稱為核定清單或優先清單。
```

## 4　AI 會回你什麼

> 以下是**示範節錄**，用來讓你知道大概會拿到什麼、以及要盯哪裡。你實際跑出來的內容一定不一樣，但下一段列的問題幾乎每次都會出現。

AI 通常會回一段開場白，然後給你一張表或一段 CSV，大致像這樣：

```
編號,中文名,英文名,人類法定分類,動物法定傳染病,WOAH,國內疫情,國際／大流行,嚴重度,傳播特性,疫苗／治療,來源,查證日,納入理由,待查項目
1,狂犬病,Rabies,第一類,是,是,台灣每年約 0 例,全球每年約 59000 死,致死率 100%,動物咬傷,有疫苗,WHO,2024,重要人畜共通傳染病,
2,狂犬病,Rabies (Lyssavirus),第一類,是,是,同上,...,...,...,...,WHO,,,,
3,登革熱,Dengue,第二類,否,否,2015 年大流行,東南亞流行,致死率低,病媒蚊,無疫苗,CDC,2024,國內疫情規模大,
...
（共 18 項）

以上為我國人畜共通傳染病優先清單。
```

先不要急著存檔。這份回覆裡至少有五個地方要改。

## 5　你一定要改的地方

逐項對照，這五類問題幾乎每次都會出現：

| AI 常見寫法 | 為什麼是問題 | 你要改成 |
|---|---|---|
| 國內疫情寫「約 0 例」 | 0 是「查過確定沒有」；沒查就寫 0 等於偽造。狂犬病的人類病例數本課尚未查 NIDSS | 改成「待查」，待查項目欄寫「NIDSS 逐病互動查詢」 |
| 來源只寫「WHO」「CDC」 | 檢查者拿這三個字回不到原始頁面 | 改成文件名稱與網址加日期，如「WHO Rabies Fact Sheet，2024-06-05」 |
| 查證日寫「2024」或空白 | 日期決定這一格什麼時候該重查 | 補成完整日期；真的不知道就整格標「待查」 |
| 同一個病出現兩次（狂犬病 / Rabies / Lyssavirus） | 同義名重複計，會讓後面每一步都算錯 | 合併成一列，英文名寫在英文名欄 |
| 收尾寫「以上為優先清單」 | 這是候選清單，不是核定清單，也還沒排序 | 刪掉，改標「課程演練候選，非機關核定」 |

**還有一個要自己判斷的**：AI 很可能把**登革熱**列進來。它疫情規模大、也是法定第二類；但在臺灣要處理的都市傳播主要是人與蚊子之間的傳播循環，沒有像日本腦炎的豬／水鳥那樣、作為本課程判定依據的脊椎動物保毒宿主，因此本課程把它排除。這不是在宣稱全球所有生態循環中絕無脊椎動物宿主；理由要寫清楚採用的是本課程的人畜共通定義與臺灣情境。可以拿日本腦炎對照：同樣是蚊媒，但豬與水鳥是實際的動物宿主，所以日本腦炎留。

反過來，AI 通常會漏掉**貓抓病**：它有明確的人畜傳播關聯，國內頻率另查，卻因為不是法定傳染病而沒有通報數。這示範的是「非法定 ≠ 不重要」。

改完之後，打開 [`candidates_tw_2026.md`](../case_data/candidates_tw_2026.md) 對一次，看你的清單漏了哪幾項。

## 6　改完應該長這樣

一列完整的候選，以**狂犬病**為例（取自課程已查證資料）：

| 欄位 | 內容 |
|---|---|
| 編號 | 1 |
| 中文名 | 狂犬病 |
| 人：法定分類 | 第一類 |
| 動：法定動物傳染病 | 是 |
| WOAH | 是 |
| 國內疫情 | 2013 年起鼬獾等野生動物持續陽性；**人類病例待查 NIDSS** |
| 國際／大流行 | 全球每年約 5.9 萬死 |
| 嚴重度 | 發病後致死率近 100%（WHO, 2024-06-05） |
| 傳播特性 | 動物咬傷／唾液，無持續人傳人 |
| 疫苗／治療 | 人用與犬用疫苗、暴露後預防皆有 |
| 納入理由 | 對應嚴重度、法定人畜雙列、WOAH、國內動物疫情四類考量 |
| 待查項目 | 人類病例數（NIDSS） |

注意三件事：

1. **嚴重度那格的條件沒被刪掉**：「發病後」三個字不能省。不是所有暴露者都必死，及時的暴露後預防可以避免發病。
2. **待查就寫待查**，同一列裡「已查證」和「待查」並存是正常的。
3. 這一列完成代表**候選有依據**，不代表已獲正式確認。

## 7　自己檢查

> 對應投影片第 22 頁「第一步驗收」。

存檔前逐項打勾，五項全過才進下一步：

- [ ] 總數落在 **15 至 30** 項
- [ ] 每一項都指得出**對應哪幾類考量**，而且附了**來源名稱與網址**
- [ ] **同義名沒有重複計兩次**（例如 Rabies 與狂犬病只能算一項）
- [ ] **集合項目的範圍有寫清楚**（例如「腸道病原」若當一項，要明列包含哪幾種）
- [ ] 全表**沒有用 0 或推測值代替待補資料**：查不到一律寫「待查」並註明去哪查；有直接來源的真實零值可以保留，須附查詢期間與條件

若第五項還沒完成，請先把沒有依據的數值改成「待查」，再交出成果。

## 8　卡住了怎麼辦

**AI 給的來源連結打不開，或打開後查無此文**：先把該欄改標「待查」，記下網址、查詢日期與錯誤情形，再從該機關的官方搜尋或另一份官方文件找可查證的來源。連結失效、登入限制或網站暫時錯誤本身不能證明來源是編造的；但在能開啟並核對前，也不能把它當成已查證。AI 提供的連結**每一條都要自己打開確認**。

**AI 只給我 8 項，湊不到 15 項**：回一句：「請補足到至少 15 項，優先從法定動物傳染病與 WOAH 列管名單中補人畜共通者。」

**AI 一直幫我排名次或說哪個最重要**：回一句：「這一步只建候選清單，不排序、不評分，請移除所有排名與重要性評語。」排序是第六步的事。

**AI 說某個病「不用列，因為資料太少」**：不接受。這套方法本來就是為資料不齊全的情境設計的，清單階段**刻意不設門檻**。此時剔除資料少的疾病，等於在還沒開始評選前就替它判定不重要。

**兩個來源數字不一樣**：這一步先不處理，兩個都先留著，第二步會教怎麼記衝突。

## 9　存檔

1. 存成 `01_candidates_tw.csv`，放進「工作坊練習」資料夾。
2. 依同一資料夾的 [`README.md`](README.md) 記錄：**課程演練候選，非機關核定清單**；不要在 CSV 資料列前另加說明列，以免下一步匯入時欄位錯位。
3. 通過檢查後，這份清單即**保存為固定版本**：之後要改必須留版本與理由。
4. 下一步要帶過去的東西：這份 `01_candidates_tw.csv`。
